# UI Core Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Give every Nova scene a retained UI canvas (layout, styles, widgets, touch handling, popups, transitions, JSON layout files with live reload) and rebuild Brick Breaker's screens on it.

**Architecture:** Each `Scene` owns a `ui::Canvas`: a pooled element tree addressed by generational handles. The App feeds it touches before `onUpdate`, runs bound callbacks at one safe point, advances animations, re-runs layout only when dirty, and draws it above the scene's world, one UI layer at a time (sprites through `SpriteBatch`, then labels through SDL_ttf). Layout files are JSON parsed by yyjson. Dev builds on desktop poll the source files and rebuild the tree in place.

**Tech Stack:** C++20 (no exceptions/RTTI), SDL3 + SDL3_ttf, yyjson 0.10.0 (new submodule), doctest, CMake.

**Spec:** `docs/superpowers/specs/2026-10-24-ui-core-design.md`

## Global Constraints

- No exceptions, no RTTI in engine and game code.
- No heap allocation on the game thread in steady-state frames: `--fail-on-alloc` stays green with UI on screen and a label changing every frame. Load/reload run inside `memory::LoadingScope`; SDL/TTF calls that allocate internally run inside `memory::DriverAllocScope`.
- All UI coordinates are design coordinates; the root box is `Renderer2D::visibleRect()`; insets come from `Renderer2D::safeArea()`.
- Every asset (layouts, theme, sprites, fonts) is opened through the existing loaders (`openAsset`, `Assets`), so release builds read them from `game.pak`.
- Missing ids, sprites, styles, fonts and bad values never crash: dev builds (`NOVA_DEV_TOOLS`) log one clear message, release builds fall back to defaults silently.
- Game code never sees SDL or yyjson: public headers live in `engine/include/nova/ui/`, everything else in `engine/src/ui/`.
- Values pinned by the spec: drag-off cancel distance **16 design px**; pressed scale **0.95** over **0.08 s**; disabled opacity **50%**; built-in corner radii **0, 8, 16, 24, 32**; outline width **2**; transition default **0.2 s**; `pop` = scale **0.85 → 1** with `Ease::OutBack` plus fade; live-reload poll **0.5 s**; popup default dim **0.6**.
- Commits end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Deleting or reloading UI from inside its own callback** (a "Close" button that removes its panel or pops its popup, a button that reloads the screen) must not touch freed elements. Tests: `Callback that removes its own panel is safe` (Task 4), `Callback that pops its own popup is safe` (Task 8), `Reload from inside a click callback` (Task 7).
2. **A finger already down when a popup opens or the screen reloads** must not click something in the new UI on release. Test: `Touch that began before a popup opened never clicks inside it` (Task 8).
3. **Rotation or a safe-area change while a popup is open** must re-layout every layer, not only the base screen. Test: `Resize re-lays out every layer` (Task 8).
4. **Labels whose text grows past their reserved capacity** (score 9 → 10 → 100) must allocate only on growth, and a size change must re-run layout of the row containing it. Test: `Label growth relayouts its row and allocates only on growth` (Task 3).
5. **Layout files with unexpected shapes** (empty `children`, a non-object child, an include cycle, a 200-element file) must load or fail with a message, never hang or crash. Test: `Loader rejects include cycles and odd shapes` (Task 6).

### Task 2: Layout

**Files:**
- Create: `engine/src/ui/layout.hpp/.cpp`, `engine/tests/test_ui_layout.cpp`
- Modify: `engine/src/ui/canvas.cpp`, `engine/src/ui/ui_backend.hpp`

**Interfaces:**
- Consumes: element store (Task 1).
- Produces:
  - `struct LayoutEnv { Rect root; Rect safeArea; f32 pixelScale; };`
  - `using MeasureFn = Vec2 (*)(const Element&, void* ctx);` — content size for `fit` (labels: measured text; images: sprite size in design units; others: {0,0}).
  - `u32 layoutCanvas(ElementStore&, const LayoutEnv&, MeasureFn, void* ctx);` returns the number of elements laid out (0 when nothing was dirty).
  - `void markLayoutDirty(ElementStore&, UiHandle);` — called by every setter that can change size or position (text, sprite, size fields, visibility, style, add/remove); `offset`, `scale` and `opacity` do **not** call it.
  - `void uiUpdate(Canvas&, f32 dt);` in `ui_backend.hpp` — for now: rebuild layout if dirty or if `LayoutEnv` changed since last frame.
- Algorithm: pass 1 bottom-up (post-order via explicit stack) computes `fit` sizes: for row/column, main axis = sum of children + gaps + padding, cross axis = max + padding; for stack, max of children + padding. Pass 2 top-down assigns boxes: stack children by `anchor` + `offset` (`fill` fills the parent's content box); row/column distribute leftover main-axis space to `fill` children by weight, then `justify`, then `align` on the cross axis (`Stretch` sets the cross size). Clamp each size by min/max. Snap each final edge with `std::round(edge * pixelScale) / pixelScale`. `safeArea: true` adds `max(0, safeArea edge − box edge)` per side to padding.

### Task 5: Toggle, Slider, ProgressBar, animations and remembered values

**Interfaces:**
- Consumes: interaction (Task 4).
- Produces:
  - `ToggleRef::onChange(std::function<void(bool)>)`; `SliderRef::onChange(std::function<void(f32)>)`, `SliderRef::onCommit(std::function<void(f32)>)`; bound by id like `onClick`.

A canvas holds 64 animation slots, reserved once; when full, the oldest finished-or-looping slot is reused and dev builds log once.
