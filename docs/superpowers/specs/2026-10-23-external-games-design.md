# External Games on Nova — Design Spec

- **Date:** 2026-10-23
- **Status:** Awaiting review
- **Builds on:** `2026-10-23-nova-engine-design.md`

## 1. Intent

Production games live in their own folders (their own git repos) **outside** the engine repo and are built on Nova. The engine repo contains only the engine, its tooling, and the Brick Breaker sample used as its test bed.

**Decisions taken with the user**

| Topic | Decision |
|---|---|
| Engine versioning | **All games use the latest engine.** One shared checkout; no per-game pinning. |
| Layout | `GameStudio/nova-engine` (renamed from `Boilerplate`) with games beside it: `GameStudio/<Game>/` |
| Brick Breaker | Stays in the engine (`games/brickbreaker`) as the sample and test bed |
| Creating games | A generator script (`tools/new_game.py`) |
| Build approach | Each game has its own top-level CMake project that includes the engine **from source** via `cmake/Nova.cmake` |

**Success criteria**

1. One command creates a game folder that builds and runs, without edits, on macOS, the iOS Simulator and Android.
2. A game folder contains no engine code. It finds the engine at `../nova-engine` by default, or at an overridden path.
3. Editing engine source changes every game on its next build (no copy, no pin).
4. Brick Breaker builds the same way an external game does (shared `Nova.cmake` and `nova-app.gradle`). All existing engine tests and the smoke test still pass.
5. Each game owns its app identity: bundle ID, display name, version and build number, orientation, icons, signing settings.

**Non-goals:** engine version pinning or a package manager, prebuilt engine binaries, a GUI project wizard, store upload automation, code signing setup itself (placeholders only).

## 3. `cmake/Nova.cmake` (the engine entry point)

Included by a game's top-level `CMakeLists.txt` after `project()`.

- **Location:** sets `NOVA_ENGINE_DIR` from `CMAKE_CURRENT_LIST_DIR/..`, using the realpath, so it works no matter who includes it.
- **Include guard:** including it twice is a no-op.
- **Project defaults:** sets C++20 (standard required, extensions off), position-independent code, and the `NOVA_SANITIZE` option. When sanitizers are on, they apply globally, as today.
- **Third-party and engine:** includes `NovaWarnings`, `NovaThirdParty` and `NovaGame`, then `add_subdirectory("${NOVA_ENGINE_DIR}/engine" "${CMAKE_BINARY_DIR}/nova")`. Third-party subdirectories are added with explicit binary dirs under `${CMAKE_BINARY_DIR}/nova-third-party/`.
- **Engine tests:** `NOVA_BUILD_ENGINE_TESTS` defaults to ON only when `NOVA_ENGINE_DIR` is the top-level source dir (`CMAKE_SOURCE_DIR`) and the platform isn't mobile. Games never build engine tests.
- **Game tests:** `NOVA_BUILD_GAME_TESTS` defaults to ON for desktop builds and drives `nova_add_game_tests()`. Both test options call `enable_testing()` when on.
- **No `CMAKE_SOURCE_DIR`:** every engine CMake file uses `NOVA_ENGINE_DIR` (or `CMAKE_CURRENT_SOURCE_DIR`) instead. Today that affects `NovaThirdParty.cmake`, `NovaGame.cmake` (the iOS templates) and `engine/tests/CMakeLists.txt` (the doctest script).
- **Engine tests' asset root:** `NOVA_TEST_ASSET_ROOT` points at `${NOVA_ENGINE_DIR}/games/brickbreaker/assets/`.

The game-side lookup lives in the game's own CMakeLists, generated by the template, because `Nova.cmake` can't find itself:

```cmake
set(NOVA_ENGINE_DIR "$ENV{NOVA_ENGINE_DIR}" CACHE PATH "Path to the nova-engine checkout")
if(NOT NOVA_ENGINE_DIR)
    set(NOVA_ENGINE_DIR "${CMAKE_CURRENT_SOURCE_DIR}/@ENGINE_REL_PATH@" CACHE PATH "..." FORCE)
endif()
if(NOT EXISTS "${NOVA_ENGINE_DIR}/cmake/Nova.cmake")
    message(FATAL_ERROR "nova-engine not found at '${NOVA_ENGINE_DIR}'. Clone it there, or configure with -DNOVA_ENGINE_DIR=<path> (or set the NOVA_ENGINE_DIR environment variable).")
endif()
include("${NOVA_ENGINE_DIR}/cmake/Nova.cmake")
```

`@ENGINE_REL_PATH@` is `../nova-engine` for the standard layout, and the generator computes it for other layouts.

## 4. `nova_add_game` and `nova_add_game_tests`

```
nova_add_game(<name>
    SOURCES <files...>
    ASSETS <dir>
    [BUNDLE_ID <id>]          default com.gamestudio.<name>
    [DISPLAY_NAME <text>]     default <name>
    [ORIENTATION Portrait|Landscape]
    [VERSION <x.y.z>]         default 1.0.0   → CFBundleShortVersionString
    [BUILD_NUMBER <n>]        default 1       → CFBundleVersion
    [IOS_PLIST <file>]        default: <game>/platforms/ios/Info.plist.in if present, else the engine default
    [IOS_LAUNCH_SCREEN <file>] same rule with LaunchScreen.storyboard)
```

- The game's `src/` is a private include dir, as today.
- The iOS plist template additionally substitutes `@NOVA_VERSION@` and `@NOVA_BUILD_NUMBER@`. Both the engine default and the game templates use them.
- `nova_add_game_tests(<name> SOURCES <files...>)` exists only when `NOVA_BUILD_GAME_TESTS` is on. It creates `<name>_tests` from the listed sources plus an engine-provided doctest main, `engine/tests/support/game_test_main.cpp`. That main sets the asset root to the game's `assets/` and the dummy SDL drivers, disables assert breaks, and installs the counting allocator. The target links `nova` and doctest and runs `doctest_discover_tests`. The game's `src/` is on its include path.

## 5. Android: shared `nova-app.gradle`

Each game's `platforms/android/app/build.gradle`:

```groovy
plugins { id 'com.android.application' }
ext.novaGameRoot = file('../../..').canonicalPath                    // game repo root
ext.novaEngineDir = file(project.findProperty('novaEngineDir') ?: "${novaGameRoot}/@ENGINE_REL_PATH@").canonicalPath
apply from: "${novaEngineDir}/platforms/android/nova-app.gradle"
android {
    namespace 'com.gamestudio.nova.host'                              // fixed; the app id below is per game
    defaultConfig {
        applicationId '@BUNDLE_ID@'
        versionCode 1
        versionName '1.0.0'
        resValue 'string', 'app_name', '@DISPLAY_NAME@'
        manifestPlaceholders += [novaOrientation: 'sensorPortrait']
    }
    // signingConfigs.release reads keystore.properties when it exists (gitignored); otherwise release is unsigned.
}
```

`nova-app.gradle` (engine-owned) configures:

- **SDK and ABIs:** compileSdk and targetSdk 36, minSdk 24, `ndkVersion 28.2.13676358`, ABIs arm64-v8a and x86_64.
- **Native build:** `externalNativeBuild.cmake.path = ${novaGameRoot}/CMakeLists.txt` with CMake `3.30.5`, staging in `${novaGameRoot}/build/android-cxx`, and arguments `-DANDROID_STL=c++_static -DANDROID_PLATFORM=android-24 -DNOVA_ENGINE_DIR=${novaEngineDir}`.
- **Java sources:** SDL's from `${novaEngineDir}/third_party/SDL/android-project/app/src/main/java`, plus `${novaEngineDir}/platforms/android/java` for `NovaActivity`.
- **Assets:** `assets.srcDirs = ["${novaGameRoot}/assets"]`.
- **Placeholders:** the `novaRenderDriver` manifest placeholder, from the property, empty by default.
- **Other:** Java 17, `lint.abortOnError false`.

Each game's Android project root has `settings.gradle`, `build.gradle` (the AGP version, as the engine uses), `gradle.properties` (including `android.suppressUnsupportedCompileSdk=36`), the Gradle wrapper (8.13), and its `AndroidManifest.xml` and launcher icons. The manifest references `com.gamestudio.nova.NovaActivity`. Brick Breaker's Android project moves to `games/brickbreaker/platforms/android` in this same shape. Its `novaGameRoot` is `games/brickbreaker`, and its engine path is `../..`.

The engine's own root `CMakeLists.txt` remains buildable for Android only through Brick Breaker's Gradle project. That project's CMake path is `games/brickbreaker/CMakeLists.txt`, which works as a top-level project, see §6.

## 6. Brick Breaker as a dual-mode project

`games/brickbreaker/CMakeLists.txt` works both ways:

- **Subdirectory of the engine root**, the default for engine development: `Nova.cmake` is already included, so it only calls `nova_add_game` and `nova_add_game_tests`.
- **Top-level project**, used by its Gradle build and by `cmake -S games/brickbreaker`: it calls `project()`, sets `NOVA_ENGINE_DIR` to `../..` and includes `Nova.cmake`, exactly as a generated game does.

Brick Breaker's level tests move from being injected into `nova_tests` to `nova_add_game_tests(brickbreaker ...)`. `ctest` from the engine root runs both suites.

## 7. Generator: `tools/new_game.py`

```
python3 <engine>/tools/new_game.py <target-dir> --name "<Display Name>" --bundle-id <reverse.dns.id>
        [--orientation portrait|landscape] [--target <cmake_name>] [--no-git]
```

- **Validation, before any write:**
  - The target must not exist, or must be an empty directory.
  - The bundle ID must match `^[A-Za-z][A-Za-z0-9]*(\.[A-Za-z][A-Za-z0-9_]*)+$`.
  - The name must be 1–30 characters with no `"`, `<`, `>` or `&`.
  - The target name defaults to the name lowercased with non-alphanumerics removed, and must match `^[a-z][a-z0-9_]*$`.
- **Placeholders:** `@GAME_NAME@`, `@GAME_TARGET@`, `@BUNDLE_ID@`, `@ORIENTATION@` (`Portrait`/`Landscape`), `@ANDROID_ORIENTATION@` (`sensorPortrait`/`sensorLandscape`), `@DESIGN_W@` and `@DESIGN_H@` (720×1280, or 1280×720 for landscape), and `@ENGINE_REL_PATH@` (POSIX relative path from the target to the engine root; Android derives its own path from `novaGameRoot`).
- **Rendering:** substitution runs over text files only (by extension list). Binary files (`.png`, `.ttf`, `.wav`, `.jar`) are copied byte for byte. `gradlew` keeps its executable bit. Files named `*.template` lose that suffix, which lets `CMakeLists.txt` and `.gitignore` live in the template without affecting the engine repo.
- **Leftovers:** any `@[A-Z_]+@` left in a rendered text file is an error and fails the generation, which is then rolled back by deleting the target dir.
- **Git:** unless `--no-git`, it runs `git init -b main`, `git add -A` and `git commit -m "Initial commit from nova-engine template"`. A failing git step only warns.
- **Next steps:** it prints the build commands for each platform.

`templates/game/` contents (what every generated game starts with):

- `CMakeLists.txt.template`, `CMakePresets.json`, `gitignore.template` (renamed to `.gitignore`) and `README.md`.
- `src/main.cpp` and `src/scenes/title_scene.{hpp,cpp}`: a sprite, a title label, and "Tap anywhere". Each tap plays a sound, pulses the sprite and logs `Tapped`.
- `tests/test_game.cpp`: one passing example test.
- `assets/`: `sprites.png` and `sprites.atlas` (two regions, generated by `gen_assets.py --template-out`), `sfx/tap.wav`, `fonts/Fredoka.ttf` and `fonts/OFL.txt`.
- `platforms/ios/Info.plist.in` and `LaunchScreen.storyboard`.
- `platforms/android/`: settings, root `build.gradle`, `gradle.properties`, `gradlew` and `gradlew.bat`, `gradle/wrapper/*`, `app/build.gradle`, `app/src/main/AndroidManifest.xml`, launcher icons (SDL's default icon set, for you to replace) and `values/styles.xml`.
- The game's `.gitignore` additionally ignores `platforms/android/keystore.properties`.

## 8. Error handling

- **Engine not found:** a CMake `FATAL_ERROR` naming the looked-up path and both override methods. On Gradle, `apply from` fails on a missing file, and the template wraps it in a check that throws a `GradleException` with the same guidance.
- **Bad generator input:** a non-zero exit with a one-line reason, and nothing written.
- **Missing iOS overrides:** if a game deletes its `platforms/ios` files, the engine defaults are used.

## 9. Testing and verification

- **`tools/test_new_game.py`** (run with `python3 -m unittest tools/test_new_game.py`) checks:
  - placeholder replacement and that no `@X@` survives;
  - landscape swaps the design size and the Android orientation;
  - the relative engine path for sibling and nested targets;
  - refusal of a non-empty target, and nothing written;
  - invalid bundle ID and name rejection;
  - binary files are byte-identical and `gradlew` stays executable;
  - `--no-git` creates no `.git`.
- **External game end to end** (a scratch target outside the repo, deleted afterwards):
  - **macOS:** configure and build the game, `ctest` (game tests), and a `--frames 600 --fail-on-alloc --screenshot` run that exits 0 with a clean leak check.
  - **iOS:** `cmake --preset ios` plus a Simulator `xcodebuild` that succeeds, then a launch and screenshot on the Simulator.
  - **Android:** `./gradlew assembleDebug`, install on the emulator only, launch and screenshot, and an `adb input tap` that produces the title scene's `Tapped` log line.
  - **Engine edit propagation:** after a trivial engine edit (a log line), the game rebuilds the engine and shows the new line without any change in the game folder. The edit is then reverted.
- **Brick Breaker regression:** the 83 engine tests plus the moved game tests, the 4200-frame smoke test, the iOS Simulator build and launch, and the Android build and run from `games/brickbreaker/platforms/android`.

## 10. Docs and finish

- **`docs/NEW_GAME.md`:** rewritten around the generator, the folder layout, how the engine path is found and overridden, the "all games use the latest engine" workflow (after engine changes, rebuild your games), versioning (`VERSION`, `BUILD_NUMBER`, Gradle `versionCode`/`versionName`), and release signing via `keystore.properties`.
- **`README.md`:** the new layout, Brick Breaker's new Android path, and a link to `NEW_GAME.md`.
- **Branch:** work happens on `feat/external-games`. Once everything is green, it's merged into `main` and pushed to `origin`.
- **Rename:** last, `GameStudio/Boilerplate` → `GameStudio/nova-engine`. Then the old build folders are deleted, everything is configured and built fresh under the new path, the tests run, and a grep of the build files shows no reference to the old path. The user continues in a new session opened on `GameStudio/nova-engine`.
