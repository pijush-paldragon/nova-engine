# Nova — 2D Mobile Engine on SDL3: Design Spec

- **Date:** 2026-10-23
- **Status:** Awaiting review
- **Scope:** Reusable 2D engine (`nova`) + sample game (`brickbreaker`) for Android and iOS, with a macOS desktop target for iteration.

## 1. Intent

A personal/studio engine reused by every future 2D mobile game and upgraded over time. Success means:

1. A new game is started by creating `games/<name>/` and one `nova_add_game()` line; Android and iOS builds work without touching platform projects beyond selecting the game.
2. Game code includes only `<nova/...>` headers and never touches SDL, EnTT or Box2D directly.
3. Deterministic memory ownership: no leaks, no dangling references, no heap allocations in steady-state gameplay frames.
4. Smooth rendering at the display's native refresh rate (60/90/120 Hz) on mid-range phones.
5. The sample Brick Breaker runs on iOS (Metal) and Android (Vulkan), and on the OpenGL ES fallback.

**Decisions taken with the user**

| Topic | Decision |
|---|---|
| Visual needs | Sprites, text, particles, tint/blend. No custom shaders in v1. |
| Renderer | SDL3 `SDL_Renderer` behind `nova::Renderer2D` (Metal/Vulkan first, OpenGL ES fallback) |
| Game model | ECS, EnTT behind a thin `nova::World` wrapper |
| v1 features | Audio, text, 2D physics, save data, tweens/timers (plus core: render, input, ECS, scenes, assets, loop) |
| Sample game | Brick Breaker |
| Dependencies | Git submodules pinned to release tags |
| Assets | Generated by a repo script; one OFL font from the official Google Fonts repo |

**Non-goals (v1):** custom shaders, hot reload, scripting languages, networking, editor tooling, skeletal animation, localisation, in-app purchases or ads.

## 2. Dependencies (git submodules under `third_party/`)

| Library | Tag | Purpose |
|---|---|---|
| SDL | `release-3.4.18` | Window, renderer, input, lifecycle, file I/O, PNG loading (`SDL_LoadPNG`) |
| SDL_ttf | `release-3.2.2` | TTF text (bundled FreeType/HarfBuzz via its vendored submodules) |

| entt | `v3.16.0` | ECS (4.0.0 exists; upgrade deferred — wrapper contains the blast radius) |

## 4. Module architecture and dependency rules

```
app ──► scene ──► ecs ──► { render, input, audio, text, physics, assets, save, tween, platform } ──► core
```

- **core**: math (`Vec2`, `Rect`, `Color`, `Mat3` affine), `Handle<T>` and `HandlePool<T>`, `FrameArena`, `Result<T>`, logging, asserts, time. No third-party dependencies.
- Each mid-layer module depends on `core` plus at most its own third-party library. The one exception is `text`, which also depends on `render`, because it draws through the same `SDL_Renderer`. Modules never include each other's private headers.
- Code that bridges components to subsystems (sprite collection, physics attach/sync and the `RigidBody` destroy hook, the tween and particle systems) lives in `ecs/`. The subsystems themselves stay ECS-agnostic.
- **ecs** wraps EnTT: `World`, `Entity`, views, and systems registered per `Phase`.
- **scene**: `Scene` base class, `SceneStack` with deferred operations, scene-owned `Timers`.
- **app**: the SDL main callbacks (`SDL_MAIN_USE_CALLBACKS`), subsystem construction order, the frame loop, lifecycle handling, and the debug overlay.
- Enforcement: third-party include directories are `PRIVATE` to `nova`, so games physically can't include them. Public headers forward-declare and use engine types only.
- Language and flags: C++20, `-fno-exceptions -fno-rtti`, warnings as errors in engine code, ASan and UBSan in macOS debug builds.

## 5. Game-facing API

### 5.1 Entry point

The engine defines `main` through SDL callbacks. The game defines exactly one function:

```cpp
nova::GameConfig nova::configureGame();   // title, designSize, orientation, org/app ids, firstScene factory
```

### 5.2 Scenes

```cpp
class Scene {
public:
    virtual ~Scene() = default;
    virtual void onEnter() {}
    virtual void onExit() {}
    virtual void onPause() {}           // another scene pushed on top, or the app went to the background
    virtual void onResume() {}
    virtual void onFixedUpdate(float dt) {}
    virtual void onUpdate(float dt) {}
protected:
    World& world();       Assets& assets();   Audio& audio();    Input& input();
    Renderer2D& renderer(); SaveStore& save(); Physics& physics(); Timers& timers();
    SceneStack& scenes(); Camera2D& camera();
};
```

- `SceneStack`: `push<T>(args...)`, `pop()`, `replace<T>(args...)`. Operations are queued and applied at the end of the frame. Only the top scene updates. Lower scenes render unless the top scene sets `opaque = true`.
- Each scene owns one `World` (ECS registry and physics world), one `Timers` and one `Camera2D`.

### 5.3 ECS

```cpp
Entity e = world().spawn();
world().add<Transform>(e, {.pos = {360, 200}});
world().add<Sprite>(e, {.region = atlas.region("ball"), .size = {24, 24}, .layer = 10});
physics().attach(e, BodyDef::dynamic().circle(12).bullet().restitution(1).friction(0));
world().addSystem(Phase::Fixed, &ballSpeedSystem);
for (auto [e, t, s] : world().view<Transform, Sprite>()) { ... }
world().destroy(e);            // deferred until end of frame
```

- Systems are free functions `void(SystemContext&)`. `SystemContext` exposes `world`, `input`, `audio`, `physics`, `dt`, `frameArena`.
- Built-in components: `Transform` (pos, rotation, scale, plus the previous pos/rot for interpolation), `Sprite`, `Text`, `RigidBody`, `Tween`, `ParticleEmitter`.

## 6. Frame loop (inside `SDL_AppIterate`)

1. `frameArena.reset()`. The input snapshot is built from the events gathered by `SDL_AppEvent`.
2. Fixed step at 60 Hz, using a time accumulator capped at 5 steps per frame. Each step copies the current transform into the previous one, steps physics, syncs bodies into `Transform`, publishes contacts, then runs the `Phase::Fixed` systems and `onFixedUpdate`.
3. Variable step: `onUpdate`, the `Phase::Update` systems, tweens, particles, timers.
4. Render with alpha = accumulator / fixedDt: interpolated transforms, collect, sort, batch, text and UI, debug overlay, present. Vsync is on.
5. Flush deferred entity destruction, then apply queued scene-stack operations.

**Lifecycle**

- `SDL_EVENT_WILL_ENTER_BACKGROUND`: stop the simulation, pause audio, flush the save, call `onPause`.
- `SDL_EVENT_DID_ENTER_FOREGROUND`: reset the accumulator, resume audio, call `onResume`.
- `SDL_EVENT_LOW_MEMORY`: release unreferenced cached assets.
- Android back button: delivered to the game as `Input::backPressed()`.

## 7. Memory and ownership

- **Ownership tree:** `App` owns its subsystems through `unique_ptr`, constructed in dependency order and destroyed in reverse. `SceneStack` owns its scenes, and each `Scene` owns its world. No raw `new` or `delete`, no owning raw pointers, no `shared_ptr` in the engine.
- **Handles:** `Handle<T>{u32 index; u32 generation}`. A lookup with a stale handle returns null and asserts in debug. Used for textures, atlases, sounds, music and fonts. Entities (EnTT) and bodies (Box2D `b2BodyId`) are generational too.
- **Asset lifetime:** each load is tagged with the requesting scene, or with `Scope::Global`. When a scene exits, assets that no scene on the stack references any more are released. Repeated loads of the same path return the same handle. On low memory, unreferenced cached entries are released.
- **Physics cleanup:** an EnTT `on_destroy<RigidBody>` hook destroys the Box2D body.
- **Zero allocations per frame:** a 1 MB `FrameArena` serves draw lists and temporary arrays, particle pools have fixed capacity, and containers are reserved on scene load. Debug builds count `operator new` calls per frame and warn when gameplay frames allocate.
- **Leak report:** on shutdown, `HandlePool`s report live entries in debug, and the smoke test fails on any.

## 8. Subsystems

### 8.1 Render

- `SDL_HINT_RENDER_DRIVER`: `metal,opengles2` on iOS, `vulkan,opengles2` on Android, `metal,opengl` on macOS. The chosen driver is logged. `SDL_SetRenderVSync(renderer, 1)`.
- Screen fitting: uniform scale `s = min(winW/designW, winH/designH)`, and the visible world rect is extended along the long axis, so there are no letterbox bars. Implemented in `Camera2D`, not with SDL logical presentation. `visibleRect()` and `safeArea()` (from `SDL_GetWindowSafeArea`) are exposed in design units.
- Batching: sprites are collected into the arena as `SpriteCmd{u64 sortKey; ...}`, where the key is layer(8) | blend(2) | texture(16) | order(16). After `std::sort`, consecutive commands with the same texture and blend mode become one `SDL_RenderGeometry` call. The corner positions are computed on the CPU, including rotation and pivot. Vertex and index buffers are reused.
- Atlases: `tools/gen_assets.py` packs the sprites into `sprites.png` plus `sprites.atlas`, a text file of `name x y w h` lines. API: `Assets::atlas("sprites")` and `Atlas::region("paddle")`.
- Missing texture: a 2×2 magenta and black checkerboard plus an error log.

### 8.2 Input

- `SDL_HINT_TOUCH_MOUSE_EVENTS=0` and `SDL_HINT_MOUSE_TOUCH_EVENTS=0`. Touches and the mouse are merged into `Pointer{id, pos (design units), delta, pressed, held, released}`, up to 10 of them.
- Queries: `pointerCount()`, `pointer(i)`, `primary()`, `tapped()`, `keyDown/Pressed(Key)` (desktop), `backPressed()`.

### 8.3 Audio (SDL3_mixer 3.2)

- `SoundHandle` is predecoded and played on pooled tracks. `MusicHandle` is streamed. `play(sfx, {volume, pitch})`, `playMusic(m, {loop, fadeInMs})`, `stopMusic(fadeOutMs)`.
- Master, sfx and music volumes, persisted through the save store by the game.
- iOS: `SDL_HINT_AUDIO_CATEGORY=ambient`.
- A missing file gives a silent handle plus an error log.

### 8.4 Text (SDL3_ttf 3.2)

- A renderer text engine (`TTF_CreateRendererTextEngine`). A `Text` component holds a font handle, string, colour, alignment and layer.
- The `TTF_Text` is rebuilt only when the string changes. Fonts are opened at design size × render scale, so glyphs are drawn at their true pixel size. Text is drawn after the sprite batches on the UI layers.

### 8.5 Physics (Box2D 3.2)

- Pixel-to-meter scale of 1 m = 100 design px, internal to the engine. `BodyDef` builder: type, box or circle shape, density, friction, restitution, bullet, sensor, fixed rotation.
- `b2BodyId` is stored in the `RigidBody` component, and the entity is stored as the body's user data.
- After each step, `b2World_GetContactEvents` and the sensor events are converted to `Contact{Entity a, Entity b, Vec2 normal}` in an arena-backed span, read with `physics().contacts()`.
- Kinematic bodies are driven with `setTargetPosition`, which sets the velocity so the body reaches the target in one step.

### 8.6 Save

- `SaveStore` holds string keys mapped to `int64`, `double`, `bool` or `string` values. The file lives in `SDL_GetPrefPath(org, app)/save.dat`, as a versioned line-based text format.
- Writes go to a `.tmp` file followed by `SDL_RenamePath`. Saving happens on background, on `flush()` and on quit. A corrupt file is logged and replaced with an empty store, never a crash.

### 8.7 Tweens, timers, particles

- `Tween` component: target property (Position, Scale, Rotation, Alpha), from, to, duration, easing (Linear, InQuad, OutQuad, InOutQuad, OutBack, OutElastic, OutBounce), loop or ping-pong, and remove-on-complete.
- `Timers` (owned by the scene): `after(sec, fn)`, `every(sec, fn)`, `cancel(id)`. They use `std::function` with captures moved in when registered, and are cleared on scene exit.
- `ParticleEmitter` component: a fixed-capacity pool with a structure-of-arrays layout, burst and rate modes, ranges for lifetime, speed and angle, colour and size over life, and additive blending. Particles are drawn through the sprite batcher.

### 8.8 Debug overlay

Toggled with F1 or a three-finger tap. Shows FPS, frame time (ms), draw calls, renderer backend, entity count and allocations per frame, drawn with SDL's built-in debug text (`SDL_RenderDebugText`).

## 9. Builds

| Target | Mechanism |
|---|---|
| macOS | Presets `macos-debug` (Ninja, ASan/UBSan) and `macos-release`. Also usable with `-G Xcode`. |
| iOS | Preset `ios` (`-G Xcode`, `CMAKE_SYSTEM_NAME=iOS`, deployment target 15.0, arm64 plus the arm64 simulator). An app bundle with assets copied as resources. The user sets the signing Team once. |
| Android | `platforms/android` Gradle project (AGP 8.x, JDK 17), minSdk 24, targetSdk 36, ABIs arm64-v8a and x86_64. `externalNativeBuild` points at the root `CMakeLists.txt` with `-DNOVA_GAME=brickbreaker`. The Java sources come from `third_party/SDL/android-project/app/src/main/java`, and the assets from `games/<game>/assets`. `SDLActivity` is subclassed only to list the native libraries to load. |

`nova_add_game(name SOURCES ... ASSETS dir BUNDLE_ID id)` creates the executable target (a `main` shared library on Android, a `MACOSX_BUNDLE` app on Apple platforms) and wires up the assets.

Asset paths are always relative (`"sprites/ball.png"`), resolved through `SDL_IOFromFile`. On iOS and macOS they're prefixed with `SDL_GetBasePath()`; on Android they read from APK assets.

## 10. Sample game: Brick Breaker

- **Scenes:**
  - **MenuScene:** title, best score, "Tap to play".
  - **PlayScene:** the game itself.
  - **PauseScene:** pushed when the app goes to the background, opaque = false, tap to resume.
  - **GameOverScene:** final score, a "new best" banner, tap to return to the menu.
- **Play:**
  - The paddle is a kinematic body, dragged horizontally by the primary pointer.
  - The ball is a dynamic circle with restitution 1, friction 0 and bullet mode. The ball speed system clamps its velocity magnitude to a constant and nudges near-horizontal angles.
  - The walls are static. The bottom is a sensor: touching it loses a life.
  - Bricks are static boxes in a grid of 8 columns by (4 + level) rows, with up to 3 hit points shown as colours.
- **Feedback:** brick break triggers a particle burst, a "break" sound and a score tween pop. Hitting the paddle plays a "hit" sound. Losing a life plays a "lose" sound and a short screen shake through the camera offset tween. Clearing all bricks moves to the next level.
- **HUD:** score, lives and level drawn with text inside `safeArea()`.
- **Save:** `best_score`, `music_volume`, `sfx_volume`.
- **Assets** (generated): `sprites.png` and `.atlas` (paddle, ball, brick, particle, white pixel), `sfx/hit.wav`, `sfx/break.wav`, `sfx/lose.wav`, `music/loop.wav` (22.05 kHz mono, streamed; no OGG encoder is installed, and the engine still supports OGG), `fonts/Fredoka.ttf` plus `fonts/OFL.txt` (fetched from `google/fonts` `ofl/fredoka`). `tools/gen_assets.py` uses only the Python standard library.

## 11. Error handling

- `Result<T>` (an expected-style type, no exceptions) for engine setup and asset loading.
- Missing or corrupt assets fall back to a checkerboard texture or silence, plus an error log. The game keeps running.
- Fatal errors (no window, no renderer from any driver): `SDL_ShowSimpleMessageBox`, then `SDL_APP_FAILURE`.
- `NOVA_ASSERT(cond, msg)` is debug-only. `NOVA_VERIFY(cond, msg)` is always evaluated and logs plus breaks in debug.

## 12. Testing and verification

- **Unit tests** (doctest, `ctest`, macOS): `Handle`/`HandlePool` (stale detection, reuse of slots, generation wrap), `FrameArena` (alignment, reset), math, the `SaveStore` round trip and corrupt-file recovery, the `World` wrapper (deferred destruction, the RigidBody hook), `SceneStack` deferred operations, tween easing endpoints, and `Timers`.
- **Smoke test:** `brickbreaker --autoplay --frames 1800` (macOS, ASan) follows the ball with the paddle and fails on any assert, sanitizer report, live handles at shutdown, or any heap allocation in frames after warm-up.
- **Device verification:** build and run on the iOS Simulator (Metal) and the Android emulator (Vulkan if the image supports it, otherwise GLES), with screenshots. The fallback is checked by forcing `opengles2` with an environment-variable override (`NOVA_RENDER_DRIVER`).
- **Physical devices:** run by the user.

## 13. Out of scope / future

Custom shaders through `SDL_GPURenderState` or an SDL_GPU backend behind `Renderer2D`, hot reload on desktop, EnTT 4.x, localisation, a UI widget toolkit, IAP and ads integration.
