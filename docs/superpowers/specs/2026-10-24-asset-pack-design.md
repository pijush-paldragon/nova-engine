# Encrypted Asset Pack — Design Spec

- **Date:** 2026-10-24
- **Status:** Awaiting review
- **Builds on:** `2026-10-23-nova-engine-design.md`, `2026-10-23-external-games-design.md`

## 1. Intent

Release builds must not expose a game's assets as browsable files inside the `.app`, `.ipa` or `.apk`. Assets are packed into one compressed, encrypted, tamper-evident file that only the game can read. This doesn't make extraction impossible, since the device must decode assets to show them. It stops casual browsing and off-the-shelf rippers, and it detects modified data.

**Decisions taken with the user**

| Topic | Decision |
|---|---|
| Layers | 1 = single pack file, 2 = encryption + integrity, 3 = release hardening |
| When | Automatically in Release configurations; Debug keeps loose files; `NOVA_PACK_ASSETS=ON` forces packing |
| Key | One **stable key per game** (future downloadable content packs must be readable); kept in a gitignored file, overridable by env var |
| Tampering | Release build **quits silently** (no message, no log), exit code 1 |
| Compression | zstd, before encryption, only where it helps |

**Success criteria**

1. A Release build of any Nova game contains `game.pak` and no loose asset files. A recursive search of the bundle, APK or IPA finds no asset file names.
2. Debug builds behave exactly as today (loose files, fast iteration).
3. Game code is unchanged (`assets().atlas(...)`, `sound(...)` and so on).
4. A modified pack, or a missing pack in Release, makes the game exit silently. Debug builds log the reason.
5. Packing is deterministic: the same assets and key give a byte-identical pack.
6. Works for Brick Breaker and for games generated by `tools/new_game.py`, on macOS, iOS and Android.

**Non-goals:** DRM, server-side delivery, anti-debugging, encrypting the save file, a content-pack download system (the stable key only keeps that possible).

## 2. Dependencies (new git submodules)

| Library | Tag | Use |
|---|---|---|
| Monocypher | `4.0.3` | XChaCha20-Poly1305 AEAD (`crypto_aead_lock/unlock`), BLAKE2b (keyed) for nonce derivation, `crypto_wipe` |
| zstd | `v1.5.7` | Compression (host tool) / decompression (runtime) |

Both are compiled from their source files. The runtime builds Monocypher plus zstd's `lib/common` and `lib/decompress` (`ZSTD_DISABLE_ASM`), and the host tool also adds `lib/compress`. Neither library's own build system is used.

## 3. Pack format v1 (`game.pak`, little-endian)

```
offset 0   header (64 bytes, authenticated as AEAD associated data of the index)
           magic      "NOVAPAK\0"  (8)
           version    u32 = 1
           reserved   u32 = 0
           indexOff   u64          offset of the encrypted index
           indexSize  u64          ciphertext length of the index (without tag)
           indexNonce 24 bytes
           reserved   8 bytes = 0
offset 64  entry data: for each entry, ciphertext followed by its 16-byte tag
indexOff   index ciphertext + 16-byte tag
```

- **Index plaintext:** `u32 count`, then per entry:
  - `u16 pathLen` and `path` (UTF-8, `/`-separated, relative to the assets root);
  - `u64 dataOff`, `u32 storedSize` (ciphertext length), `u32 originalSize`;
  - `u8 compression` (0 = none, 1 = zstd);
  - `nonce[24]`.

  Entries are sorted by path.
- **Entry encryption:** `crypto_aead_lock(key, nonce, ad = path bytes, stored plaintext)`, where the stored plaintext is the zstd frame or the raw bytes. Binding to the path stops swapping entries.
- **Nonces:**
  - per entry: the first 24 bytes of keyed BLAKE2b-256 over `"nova-entry" || path || 0x00 || compression byte || stored bytes` (what is actually encrypted, so a changed zstd output for the same file never reuses a nonce under the stable key), keyed with the pack key;
  - for the index: the same construction over `"nova-index" || index plaintext`.

  This makes output deterministic. Nonces only repeat for identical key, path and content, which reveals only equality.
- **Compression:** zstd level 19. It's used only if `compressed ≤ 0.95 × original`.
- **Limits:** a single asset can't exceed 4 GiB; the pack can't exceed 2^63.

## 4. Key handling

- **Format:** the key is 32 bytes, stored as 64 hex characters.
- **Resolution, at configure time:**
  1. The `NOVA_PACK_KEY` environment variable, which must be 64 hex characters.
  2. Otherwise `<game source dir>/.nova/pack.key`.
  3. Otherwise generate it with `nova_pack keygen` (OS CSPRNG: `arc4random_buf` on Apple, `getrandom` on Linux), write it, and print a CMake `WARNING` asking the user to back up `.nova/pack.key`, without which future content packs can't be read by released apps.
- **Embedding:**
  - CMake runs `nova_pack embed-key` to generate `${CMAKE_CURRENT_BINARY_DIR}/nova_pack_key.cpp`, which defines `void nova::detail::packKey(uint8_t out[32])`.
  - It holds four 32-byte arrays `s0..s3` in separate translation-unit-local variables (`volatile` reads), with `key = s0 ^ s1 ^ s2 ^ s3` and fresh random `s0..s2` on every regeneration.
  - The file is compiled into the game target (Debug and Release alike).
  - The key never appears contiguously in the binary.
- **Gitignore:** `.nova/` is added to the engine `.gitignore` and to the game template's `.gitignore`.

## 5. Host tool `nova_pack`

- **Source:** `tools/nova_pack/` (`CMakeLists.txt`, `main.cpp`, `pack_format.hpp/.cpp` shared with the runtime reader for the constants and layout).
- **Built at configure time:** `Nova.cmake` builds it for the build machine with `execute_process` (`cmake -S tools/nova_pack -B ${CMAKE_BINARY_DIR}/nova-host -DCMAKE_BUILD_TYPE=Release`, plus `cmake --build`). Any toolchain variables are cleared, so iOS and Android configures still produce a macOS binary.
- **Commands:**
  - `nova_pack keygen <file>`
  - `nova_pack embed-key <keyfile-or-env> <out.cpp>`
  - `nova_pack pack <assets-dir> <out.pak>`, with the key from `NOVA_PACK_KEY`, else `--key-file <file>`
  - `nova_pack verify <in.pak>`, which decrypts everything; exit 0 or 1
- **Pack inputs:** every regular file under the assets dir, except dot-files.
- **Errors:** non-zero exit and a message; partial output is removed.

## 6. Build integration

**Option:** `NOVA_PACK_ASSETS` (BOOL, default OFF) forces packing in every configuration. Release-type configurations (`Release`, `MinSizeRel`, `RelWithDebInfo`) always pack.

- **Apple (macOS Ninja, macOS Xcode, iOS Xcode):**
  - Assets are no longer added as bundle sources.
  - A `POST_BUILD` custom command on the game target runs `cmake -P cmake/NovaStageAssets.cmake` with `CONFIG=$<CONFIG>`, `FORCE`, `SRC`, `DEST=$<TARGET_BUNDLE_CONTENT_DIR:...>/<Resources>` (`Contents/Resources` on macOS, the bundle root on iOS), `TOOL`, `KEYFILE` and `ENV` key handling.
  - That script either copies the asset tree, or runs `nova_pack pack` to `DEST/game.pak`, after first deleting any staged assets from the other mode.
  - Xcode runs this script phase before its CodeSign phase.
- **Android:**
  - `nova-app.gradle` passes `-DNOVA_PACK_ASSETS=ON` for the `release` build type.
  - The native build writes the pack to `${novaGameRoot}/build/android-pack/<buildType>/game.pak`, using a `POST_BUILD` step on the `main` target that runs `NovaStageAssets.cmake` with `DEST` set to that folder.
  - The `release` source set uses `assets.srcDirs = [that folder]`; the `debug` source set keeps `${novaGameRoot}/assets`.
  - `merge<Variant>Assets` depends on `externalNativeBuild<Variant>` (the SDL template rule).
  - `androidResources.noCompress 'pak'`.
- **Runtime requirement flag:** in pack mode the game target gets `NOVA_REQUIRE_PACK=1` (a per-config generator expression on `entry.cpp` and the generated key file, compiled into the game target). This tells the runtime that a missing pack is tampering.
- **Hardening, release-type configurations only, on `nova` and game targets:**
  - `-fvisibility=hidden -fvisibility-inlines-hidden`;
  - `INTERPROCEDURAL_OPTIMIZATION ON` (if `check_ipo_supported`);
  - `-ffunction-sections -fdata-sections` with `-Wl,-dead_strip` (Apple) or `-Wl,--gc-sections` (Android);
  - Xcode `DEPLOYMENT_POSTPROCESSING=YES`, `STRIP_INSTALLED_PRODUCT=YES`, `STRIP_STYLE=all` (Release);
  - macOS Ninja release: a post-build `strip -x` on the executable;
  - Android: AGP already strips release `.so`.
- **Developer switches:** `NOVA_RENDER_DRIVER`, `NOVA_LOG_INPUT`, `NOVA_DEBUG_OVERLAY` and `NOVA_ALLOC_TRAP` are read only when `NOVA_DEV_TOOLS` is defined. That's defined for non-release configurations, and for any `NOVA_PACK_ASSETS=ON` Debug build. The F1 and three-finger overlay toggle stays in non-release only. Command-line flags remain on desktop only, since phones don't have them.

## 7. Runtime

- **No public API changes.** The engine-internal `engine/src/platform/asset_io.hpp` declares
  - `SDL_IOStream* openAsset(std::string_view rel)` (nullptr if missing; the caller closes it),
  - `bool mountPack(std::string_view packRel)`,
  - `bool packMounted()`,
  - `void unmountPack()`.
- **Callers switch to `openAsset`:**
  - `readFile` and `readTextFile`;
  - `RendererBackend::loadTexture` (`SDL_LoadPNG_IO(io, true)`);
  - `AudioBackend::loadSound` and `loadMusic` (`MIX_LoadAudio_IO(mixer, io, predecode, true)`);
  - `TextBackend::loadFont` (`TTF_OpenFontIO(io, true, size)`).
- **Pack reader (`engine/src/platform/pack_reader.{hpp,cpp}`):**
  - **Mount:** opens `assetPath("game.pak")` (APK assets on Android), reads and validates the header, decrypts the index, and builds a sorted path table. The key is retrieved with `packKey()` into a local buffer and copied into the reader. All temporaries are wiped with `crypto_wipe`; the key is wiped on unmount.
  - **Asset reads:** each one reads `[dataOff, storedSize + 16)`, verifies and decrypts with the path as associated data, and decompresses (zstd) if flagged. It returns `SDL_IOFromDynamicMem` holding the original bytes, positioned at 0.
- **Mounting:** `App::init` calls `mountPack("game.pak")` before any asset load.
- **Tamper handling:** a `[[noreturn]] void nova::detail::assetIntegrityFailure()` function.
  - In release-type builds (no `NOVA_DEV_TOOLS`) it calls `std::_Exit(1)`, with no log and no message box.
  - In dev builds it logs `"Asset pack integrity failure: <reason>"` and then calls `std::_Exit(1)`.
  - **Triggers:**
    - a missing pack when `NOVA_REQUIRE_PACK`;
    - a bad magic or version;
    - index authentication failure;
    - an entry authentication or zstd failure;
    - an out-of-range offset.
  - An asset that's absent from the index returns nullptr: a normal missing asset, giving a checkerboard or silence.
- **Debug with a pack present:** if `game.pak` exists, it's used. Otherwise loose files are used.

## 8. Testing

- **Engine unit tests (`nova_tests`)** use a fixed test key file in `engine/tests/data/test.key`. A CMake custom command builds `${CMAKE_BINARY_DIR}/test-assets.pak` from Brick Breaker's assets with `nova_pack`, and the tests link a test `packKey()` definition. They cover:
  - mounting and reading every asset, byte-identical to the loose file;
  - `readFile`, `loadTexture` (software renderer), audio (dummy driver) and fonts all going through the pack;
  - zstd being used for `.wav` and `.ttf` and not for `.png` (index inspection through a test-only accessor);
  - tamper cases: flipping one byte in the header, in an entry's data and in the index, plus truncation and a wrong key, all detected. These tests use a non-exiting failure hook (`setIntegrityFailureHandlerForTests`) to observe the failure;
  - an unknown path returning nullptr without counting as an integrity failure;
  - determinism: packing twice gives identical bytes.
- **Brick Breaker macOS release:**
  - the bundle contains `game.pak`, and `find`/`grep -r` finds no asset names (`sprites`, `.wav`, `.ttf`) anywhere in the `.app`;
  - `--autoplay --frames 1800` exits 0;
  - a copy with one flipped byte in `game.pak` exits 1 with empty stdout and stderr;
  - a copy with `game.pak` deleted exits 1 silently;
  - `nm` on the executable shows no `nova::` symbols exported.
- **iOS:** a Release Simulator build bundle contains `game.pak` and no loose assets, and the game launches and renders on the Simulator. A Debug build still has loose assets.
- **Android:** `assembleRelease` produces an APK where `assets/game.pak` is present and `STORED` (uncompressed) and no other asset is present. For the test, the APK is signed with the debug keystore, then installed on the emulator, where it runs (logcat shows the renderer). `assembleDebug` still has loose assets.
- **Generated game:** a release build of a fresh `new_game.py` game passes; `.nova/pack.key` is created and gitignored.
- **Regression:** all existing tests pass, and the Debug smoke run is unchanged.
